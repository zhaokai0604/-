# 简析智评项目介绍方案

> 用途：项目答辩、路演汇报、申报书“项目介绍”章节。建议按 5 分钟讲解，PPT 可拆成 8～10 页。

## 一、项目一句话定位

简析智评是一套面向高校就业场景的简历评价智能体。它把学生的单份简历诊断、岗位匹配与优化交付，和教师的班级就业能力洞察连接起来，形成“学生诊断—教师改进—岗位与简历质量沉淀”的就业数据治理闭环。

核心表达：**先匹配、再护航、后交付**。

## 二、项目背景

高校毕业生求职从“有没有简历”转向“简历是否能被岗位准确理解”。学校一端积累了大量简历、岗位和就业指导记录，但这些材料通常是非结构化文档，难以形成可比较、可追踪、可复用的数据资产。学生需要及时、具体的修改意见；辅导员和就业教师需要看到班级共性短板；学校还需要在保护个人隐私的前提下沉淀岗位需求和培养反馈。

因此，本项目将简历视为一种可治理的就业数据对象：先把文档转成结构化证据，再给出可解释的诊断和岗位匹配，最后形成优化稿、报告和班级统计，而不是只返回一段聊天式建议。

## 三、当前痛点

### 1. 学生侧痛点

- 不知道简历缺什么：经历描述常停留在职责罗列，缺少成果、数据和岗位关键词。
- 获得的建议不稳定：不同工具评分口径不同，建议笼统，难以确认修改是否有效。
- 简历格式复杂：表格、双栏、扫描 PDF、文本框可能造成机器漏读，学生却容易把“机器没读到”误判为“自己写得差”。
- 目标岗位不清晰：只看总分，无法知道哪些能力与目标岗位相关、哪些要求尚未满足。

### 2. 教师侧痛点

- 逐份人工批改耗时，难以覆盖全班并保持统一标准。
- 只能看到个体材料，难以聚合专业、年级、班级的共性问题。
- 反馈难以沉淀为课程任务，缺少“发现短板—组织训练—再次验证”的闭环。

### 3. 管理与数据侧痛点

- 简历、岗位和报告分散在文件夹中，缺少版本和审计记录。
- 真实简历含有姓名、电话、邮箱、学校等敏感信息，不能直接进入训练集或对外材料。
- 仅报告“分析成功率”会掩盖扫描件不可读、板块识别不确定等风险，容易造成指标失真。

## 四、需求分析

### 4.1 目标与原则

项目目标是让系统在可复现、可解释、可保护隐私的前提下，完成从简历接入到改进交付的闭环。需求遵循四项原则：

1. **结果可执行**：输出完整优化稿和具体证据缺口，不止给分数。
2. **结论有依据**：规则负责硬约束和风险，语义通道负责相关性排序，生成模块负责表达和交付。
3. **不确定性可见**：区分链路完成、文本可读和分析可信，解析质量不足时告警或封顶。
4. **数据最小化**：原始简历本地处理；教师默认只看统计，不看全班正文；脱敏样本分池管理。

### 4.2 目标用户

| 用户 | 主要任务 | 核心价值 |
|---|---|---|
| 学生/求职者 | 上传简历、选择岗位、查看诊断、修改并比较版本 | 获得可执行修改路径和岗位针对性反馈 |
| 就业教师/辅导员 | 查看班级分布、共性短板和学生概览 | 降低批改成本，将数据转成教学任务 |
| 就业管理者/管理员 | 管理用户、岗位模板、系统配置和审计 | 统一管理、权限隔离和过程可追溯 |

### 4.3 功能需求

**学生端**

- 支持 DOCX、文字版 PDF，扫描 PDF 可选 OCR；支持单份和 ZIP 批量分析。
- 自动识别教育、经历、项目、技能、获奖等板块并结构化抽取。
- 从完整性、经历、语言、格式、亮点、岗位匹配六个维度诊断。
- 展示命中/缺失技能、学历等硬约束、证据片段和可信度提示。
- 生成基于初稿的优化稿 DOCX，无法确认的内容标记“待补充”，并提供初稿与优化稿 Diff。
- 支持岗位库筛选、相关岗位 Top5、历史版本 Δ 分、Word/PDF 报告和模拟面试。

**教师端**

- 按班级、专业、年级查看评分分布、共性问题和学生概览。
- 将高频短板聚合为可直接使用的训练/课程模板。
- 不默认展示简历正文，遵循最小可见原则。

**管理端**

- 用户角色和状态管理、岗位模板管理、评分/AI 配置、审计日志。
- 花名册导入、多租户组织隔离、存储清理和部署健康检查。

### 4.4 非功能需求

- **可靠性**：云端 AI、OCR、语义模型不可用时可降级，不丢失本地结果。
- **安全性**：会话隔离、密码哈希、角色校验、敏感信息脱敏、原始简历不进 Git。
- **可解释性**：每项诊断尽量对应证据、规则或岗位要求。
- **可复现性**：记录版本、配置、样本口径和生成时间；测试集不参与 Prompt 或参数选择。
- **可部署性**：Windows 双击启动；支持 SQLite 演示和 MySQL、Docker 生产部署。

## 五、总体技术方案

### 5.1 三擎架构

```text
上传简历 / 岗位 JD
        |
        v
语义理解引擎：理解简历与岗位的语义关系，完成匹配排序
        |
        v
证据护航引擎：规则评分、学历/经验硬约束、风险拦截、可信度分层
        |
        v
生成交付引擎：诊断建议、优化稿、Diff、报告、模拟面试
```

- **语义理解**：本地 sentence-transformers/SBERT（可选）与分词、同义词、IDF 基线结合，用于岗位相关性排序。
- **证据护航**：分节解析、六维规则评分、低信噪比纠偏和硬约束核验，避免无证据高分，并解释“为什么这样判断”。
- **生成交付**：可调用外部大模型增强表达；无 API Key 或调用失败时使用本地模板回退。DeepSeek 只是可选云端实现，不是项目唯一引擎。

### 5.2 业务处理链路

1. **接入**：上传文件，校验格式、大小和 ZIP 安全；SSE 推送实时中间事件。
2. **读取**：DOCX/PDF 文本提取，扫描件进入 OCR 分支；识别版式复杂度和正文可读性。
3. **解析**：按标题和语义线索划分板块，抽取教育、经历、项目、技能和获奖等结构化字段。
4. **评价**：计算六维诊断，记录证据覆盖、质量告警和 score reliability。
5. **匹配**：结合岗位关键词、语义相关性和硬约束，返回命中项、缺失项及推荐岗位。
6. **交付**：生成优化稿、Diff、报告和后续面试训练；保存版本链，支持复盘改进。

### 5.3 开发工具与技术栈

| 层次 | 工具/技术 | 用途 |
|---|---|---|
| 前端 | Vue 3、Vite、Vue Router、ECharts、lucide-vue-next | 单页应用、路由、评分图表和交互界面 |
| 后端 | Python、FastAPI、Uvicorn | REST API、分析编排和实时 SSE |
| 文档处理 | python-docx、pdfplumber、Pillow、OCR 依赖 | DOCX/PDF 读取、图片处理和扫描件识别 |
| 算法 | jieba、规则引擎、sentence-transformers（可选） | 分词、关键词核验、语义匹配和回退 |
| 数据与任务 | SQLAlchemy、SQLite/MySQL、Redis/Celery（可选） | 记录、组织隔离和异步任务 |
| 交付 | ReportLab、DOCX 模板、ZIP 服务 | 报告、优化稿和批量下载 |
| 工程工具 | VS Code/Cursor、Git、Docker Compose、pytest、Chrome/Edge | 编码协作、部署、测试和演示 |

## 六、数据治理与安全方案

真实简历只在本地处理，先字段级脱敏，再生成匿名 TXT 和稳定样本 ID。样本按 A/B/C 池管理：A 池用于双人独立标注、第三方裁决和解析评测；B 池用于复杂版式和能力边界；C 池仅用于演示，不进入训练和正式测试。教师端只返回必要的统计元数据，用户记录按会话、组织和角色隔离。只有用户主动开启增强并配置有效 API Key 时，文本才会发送到云端服务。

## 七、验证方式与当前证据

项目不把不同含义的数字合并成一个“准确率”，采用三层口径：

| 层级 | 当前结果 | 能证明什么 |
|---|---:|---|
| L1 链路 | 59 份分析成功率 100%，护栏测试 4/4 | 上传、分析、交付链路可运行 |
| L2 可读 | 59 份无 OCR 基线可读率约 55.9%；开启 OCR 后 PDF 可读性提升 | 扫描 PDF 必须进入 OCR 分支 |
| L3 可信 | A 池前 15 条经第三方裁决，板块 micro F1=0.9785（P≈0.97，R≈0.99） | 脱敏裁决样本上的板块识别能力 |

边界必须主动说明：L3 不是字段级准确率或全库泛化；`projects` 板块 F1 约 0.83，复杂版式仍可能发生边界混淆。61 条弱标注匹配实验存在同源拟合风险，只能作为探索附录，不能作为主答辩泛化结论。

## 八、项目创新与落地价值

1. **三擎职责分离**：把语义排序、规则证据和生成交付拆开，兼顾效果、解释和离线可用。
2. **可信度分层**：明确区分“系统跑完了”“系统读到了”“结论足够可信”，降低误用风险。
3. **证据驱动的优化稿**：以初稿和证据为边界，不编造经历；缺失信息标“待补充”，并用 Diff 验证修改。
4. **学生到教师的闭环**：单份简历结果沉淀为版本数据和班级共性短板，支持教学改进。
5. **数据治理内置**：脱敏、分池、权限、审计和可复现验收从设计阶段进入系统，而不是事后补丁。

## 九、推荐答辩结构（8 页 PPT）

1. **背景与价值**：高校就业数据非结构化，学生、教师、管理者各有痛点。
2. **问题定义**：机器可能没读懂，建议可能没证据，教师缺少班级视角。
3. **用户与需求**：学生、教师、管理员三类用户及核心任务。
4. **产品闭环**：上传—解析—诊断—匹配—优化—复盘—班级洞察。
5. **技术架构**：三擎协同和工程处理链路。
6. **关键创新**：可信度分层、低信噪比护栏、优化稿 Diff、岗位知识库。
7. **验证与边界**：按 L1/L2/L3 分栏报告，说明样本口径和不能外推的结论。
8. **演示与展望**：两分钟主路径，最后说明 OCR、复杂版式、样本规模和校级合规建设方向。

## 十、可直接口述的项目介绍词（约 3 分钟）

“我们开发的是简析智评，一套面向高校就业场景的简历评价智能体。项目关注的不是给简历简单打一个分，而是解决三个实际问题：第一，复杂 DOCX、双栏和扫描 PDF 可能导致机器漏读；第二，传统大模型建议常常缺少岗位证据，甚至存在编造风险；第三，教师能批改单份简历，却很难从全班数据中发现共性短板。

针对这些问题，我们把系统设计成学生、教师、管理三端闭环。学生上传简历并选择目标岗位后，系统完成正文提取、OCR、板块解析、六维诊断和岗位匹配，给出命中与缺失依据，并基于初稿生成可下载优化稿。不能从原文确认的信息会标记‘待补充’，不会凭空增加经历；用户还可以通过 Diff 和版本 Δ 分核对修改效果。教师端不直接浏览全班正文，而是查看班级分布、高频问题和一键成课模板，把个体结果转成教学行动。

技术上采用‘语义理解、证据护航、生成交付’三擎架构。语义通道负责理解简历和岗位的相关性并排序；规则层负责学历、经验等硬约束、低信噪比纠偏和证据解释；生成模块负责建议、优化稿、报告和模拟面试，云端模型只是可选增强，没有 Key 时也能离线运行。前端使用 Vue 3、Vite 和 ECharts，后端使用 FastAPI，文档处理采用 python-docx、pdfplumber 和 OCR，数据层支持 SQLite 或 MySQL，部署支持 Docker。

我们对结果采用分层验证。59 份样本分析链路成功率是 100%，说明系统能跑通并完成交付；无 OCR 时可读率约 55.9%，说明扫描 PDF 必须进入 OCR 分支；A 池前 15 条脱敏样本经第三方裁决后，板块识别 micro F1 为 0.9785。这里的 F1 只说明裁决样本上的板块识别，不等于字段级准确率或全库泛化，项目板块仍存在边界混淆。我们坚持把不确定性和数据边界讲清楚，让系统既能用，也能被复核。

简析智评的价值，是把一次简历分析变成可解释、可追踪、可用于教学改进的就业数据闭环。”

## 十一、答辩时不要这样说

- 不要把 59 份成功率说成“解析准确率 100%”。
- 不要把 OCR 可读率说成 OCR 准确率。
- 不要把 61 条同源弱标注匹配实验写成模型泛化指标。
- 不要宣称系统可以自动淘汰学生或替代招聘决定。
- 不要说“数据绝不会外传”；准确表述是主链路支持本地运行，用户主动配置并开启云端增强时才调用外部服务。

## 十二、结尾页建议

> **简析智评：让简历评价从一次性打分，变成有证据、有边界、可交付、可复盘的高校就业数据治理闭环。**
