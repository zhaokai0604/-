> 用于国赛技术说明 / 答辩**补充附录**。数据来自本地评测脚本与工程实现。  
> 总体规划见 [`docs/深度优化方案.md`](深度优化方案.md)；**主 PPT 数字以** [`赛前收口完成.md`](赛前收口完成.md)、[`答辩材料速查.md`](答辩材料速查.md) **为准**。

> **口径强制：** 本文第 2、3 节的模型消融属于历史探索性实验。样本曾参与调参、α 拟合或模型选择，**不得作为平台泛化验收结论，禁止把 0.9056 / +0.24 贴进主答辩页**。当前主实验为《平台能力验收实验方案.md》中的功能、鲁棒性、护栏、提示词回归和性能实验，以及 A 池裁决后板块 F1。

## 1. 核心创新点（可答辩 · 主线）

### 1.1 规则可解释底座 + 三擎协同

- **证据护航引擎**：关键词 / 岗位画像 / 硬约束 / 证据片段，保证可解释、可离线（本地算法，非深度模型）  
- **语义理解引擎**：本地双塔 / 分词语义，完成简历–岗位匹配排序  
- **生成交付引擎**：优化稿、报告、面试；云端大模型仅为可选实现，失败回退本地模板  
- **当前策略**：对外统一称「简析智评三擎」；不把小样本微调 Spearman 作为平台验收依据；**不称 DeepSeek 引擎**

### 1.2 证据置信度与低信噪比纠偏

- 输出 `evidence_confidence` 与「待补充区（低信噪比）」  
- 当「经历/岗位相关性高但证据弱」时强制扣分  
- 贴合真实 HR：**宁愿信数据，不信散文**

### 1.3 交付物升级：基于初稿的优化稿

- 主交付不是建议清单，而是可下载的完整优化稿 DOCX  
- 详情页提供初稿 ↔ 优化稿 Diff  
- 硬约束：不编造经历；不足处标记【待补充】

### 1.4 体验层：实时解析流 + 版本时光机 + 可信度分层

- 分析流水线通过 `event_sink` 推送真实中间事件  
- 详情页 SSE 重放「阅读—命中—低信噪比—评分」过程  
- 多版本六维 Δ 分箭头对比（版本时光机）  
- 详情 / 报告分栏：**链路｜可读｜可信**

### 1.5 轻量岗位技能图谱 + 教师端一键成课 + 岗位适配依据

- 父子技能层级提示（如 Python → 数据分析）  
- 岗位库相关 Top5 与命中 / 缺失依据  
- 教师端基于共性问题生成训练任务与推送文案  
- **只推聚合短板模板，不暴露学生简历正文**

## 2. 消融与基线对比（历史探索附录 · 禁止主 PPT）

> 下列 Spearman / α 数字仅证明「做过对照实验且可复现」，**不是**平台准确率。

### 2.1 评测集

- 路径：`data/eval/match_cases.json`  
- 规模：50+ 脱敏合成简历-岗位对  
- 标签：1–5 相关度（人工弱标注）  
- 构建脚本：`backend/scripts/build_match_eval_set.py`  
- 评测脚本：`backend/scripts/eval_match_baseline.py`

### 2.2 指标定义

- **Spearman(label, score)**：排序一致性  
- 对比通道：
  - Rule-only（关闭语义）
  - Semantic-only（分词/同义向量）
  - Fused（规则+语义；若存在 blender 则用学习融合）

### 2.3 近期本地结果（61 条评测集）

**A. 分词语义基线**（同义扩展 + IDF + α 融合，未开 SBERT）：

| 通道 | Spearman |
|------|----------|
| Rule | 0.6543 |
| Semantic（jieba） | 0.7850 |
| Fused | 0.7950 |
| Fused − Rule | +0.1407 |

**B. 微调双塔后**（`train_sbert.py` → `data/models/sbert-resume-match`，`USE_SEMANTIC_MODEL=true`，α≈0.37）：

| 通道 | Spearman |
|------|----------|
| Rule | 0.6543 |
| Semantic（SBERT） | **0.9056** |
| Fused | **0.8919** |
| Fused − Rule | **+0.2376** |

同义召回：`da-synonym`（pandas≈Python）在分词通道约 31+；SBERT 通道整体排序显著抬升。

> 复现：`build_match_eval_set.py` → `train_sbert.py` → `train_biencoder.py` → `eval_match_baseline.py`。  
> 上传分析：`POST /resumes/analyze-direct`（`stream:true`）→ `GET /history/{id}/analysis-live` 边推事件边落库。

### 2.4 附录对照表（勿贴主答辩页）

| 配置 | 说明 | 探索集现象（弱标注，非泛化） |
|------|------|----------|
| A 仅规则 | `USE_SEMANTIC_MATCH=false` | 可解释强，同义表达易漏 |
| B 规则+分词语义 | `USE_SEMANTIC_MODEL=false` | 同源集上排序约 +0.14 |
| C +微调双塔 | `USE_SEMANTIC_MODEL=true` | 同源集语义 Spearman≈0.91，融合约 +0.24 |
| D +blender | `data/models/match_blender.json` | α 贴合同源标注（隔离不足） |
| E +低信噪比惩罚 | 默认开启 | 空泛经历降分（**可主讲**） |

**主答辩应贴的表**：成功率｜可读率｜裁决后板块 F1（见答辩材料速查 §0）。
