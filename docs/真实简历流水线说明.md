# 真实简历流水线说明（脱敏 → 分拣 → 能力边界卡）

> 用途：处理校内/自备真实简历时的**隐私安全**与**赛前材料**，不是再训一套 SBERT 的捷径。  
> 相关脚本：`backend/scripts/anonymize_resumes.py`、`classify_resumes.py`、`capture_bad_cases.py`

---

## 0. 硬红线（三人必须遵守）

| 禁止 | 原因 |
|------|------|
| 用大模型给 60 份简历自动打匹配 1–5 分再训练 | 循环验证，答辩送命 |
| 把 60 份全部塞进 `train_sbert.py` | 过拟合真实模板，消融数字可能崩 |
| 未脱敏姓名/手机写入 JSON 或提交附件 | 隐私红线，国赛风险 |
| 把 C 池当训练集 | C 池只允许现场演示 |

**正确用法**

- A 池 → 人工标 `gold_sections` 后做**解析评测**  
- B 池 → Bad Case / 能力边界卡（答辩）  
- C 池 → 演示备用，不进训练  

匹配模型主叙事仍用现有 `match_cases.json`（61 条）+ 已微调权重。

```text

    └── bad_cases/

        ├── boundary_card.csv
```

## 2. 一键顺序

```bash
cd backend

# 1）把 60 份 docx/pdf 放进 ..\data\raw_real_resumes\

# 2）脱敏
.\.venv\Scripts\python.exe scripts\anonymize_resumes.py

# 3）人工抽查至少 5 份 anonymized_real_resumes\*.txt

# 4）分拣 A/B/C
.\.venv\Scripts\python.exe scripts\classify_resumes.py --a-size 15 --b-size 10

# 5）人工看 pool_summary.md；若改了 classify_report.json 的 pool 字段：
.\.venv\Scripts\python.exe scripts\classify_resumes.py --from-report ..\data\resume_pools\classify_report.json

# 6）B 池能力边界卡
.\.venv\Scripts\python.exe scripts\capture_bad_cases.py
```

扫描版 PDF 评测可显式启用本地 OCR：

```powershell
.\.venv\Scripts\python.exe scripts\anonymize_resumes.py --ocr
.\.venv\Scripts\python.exe scripts\classify_resumes.py --manifest ..\data\anonymized_real_resumes\anonymize_report.json
```

`--ocr` 只把识别文本送入脱敏流程，不重写扫描 PDF。未安装 PaddleOCR 时，报告会将文件标记为 `ocr_failed`，不会伪造解析成功。

可选截图（需前端已启动 + playwright）：

```bash
.\.venv\Scripts\python.exe scripts\capture_bad_cases.py --screenshot
```

## 3. 脚本边界能力（为何能应付“格式不统一”）

### 3.1 脱敏 `anonymize_resumes.py`

覆盖：手机、邮箱、身份证、微信/QQ、URL/GitHub、地址标签值、学校实体、公司实体。  

姓名策略（重要）：

- **只**替换「姓名：xxx」标签与**首行短专名**  
- **禁止**全文 2～4 个汉字盲替（否则「数据分析」会被毁掉）  
- 黑名单：专业/技能/城市/评价套话等  

格式边界：

| 输入 | 行为 |
|------|------|
| docx | 输出脱敏 `.txt` + 尽量改写段落/表格后的 `.docx`（文本框可能残留 → **以 txt 为准**） |
| pdf | **只输出 txt**，不重写扫描件像素（避免半脱敏图片外泄） |
| 空文件 / `~$` 临时锁 | 跳过 |
| 抽正文失败 | 记入 report，不中断整批 |

### 3.2 分拣 `classify_resumes.py`

自动算：

- `layout_complexity`：行数、短行比例、表格痕迹、粘连长行  
- `content_quality`：板块数、量化词、求职意向、正文长度  
- A = 高内容质量 − 低复杂度；B = 高复杂度；其余 C  

支持 `--from-report`：你改完 pool 字段后只重新复制文件。

### 3.3 边界卡 `capture_bad_cases.py`

默认**本地离线**调用本仓库解析/评分（`enable` 语义关闭以加快批跑），不走异步上传 API。  
输出 `boundary_card.md` / `.csv`，含：版式特征、parse_quality、核心告警、总分、系统行为（降权/提示换文字版）。

## 4. 脱敏后人工检查清单

打开任意 5 份 `anonymized_real_resumes/*.txt`：

- [ ] 无 11 位手机号、邮箱、身份证  
- [ ] 姓名多为 `【姓名】`，正文技能句没被刷成姓名  
- [ ] 学校多为 `【高校】`  
- [ ] 扫描 PDF 若几乎无字，应改用文字版再进流水线  

---

## 5. 答辩可用表述

> 我们构建了脱敏流水线，对真实简历做字段级不可逆清洗；再按版式复杂度与内容丰富度分为评测池、边界池与演示池。边界池由脚本生成能力边界卡——复杂版式会告警并降权，而不是虚高打分。

## 6. 与模型微调的关系

| 动作 | 是否推荐 |
|------|----------|
| A 池人工标板块 → 解析 F1 | ✅ 推荐 |
| B 池边界卡上 PPT | ✅ 推荐 |
| C 池现场演示 | ✅ 推荐 |
| 全量进 `train_sbert` | ❌ 禁止 |
| LLM 自动打匹配分再训 | ❌ 禁止 |
