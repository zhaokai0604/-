## 一、赛题对齐与现状（写实）

### 1.1 产品定位（当前）

> **职教组就业数据治理闭环**：学生诊断 → 教师班级洞察 → 岗位与简历质量沉淀。  
> 不是「纯 AI 打分器」；工程可交付，证据链按成功率｜可读性｜可信度分栏。

### 1.2 国赛评分结构

| 评分项 | 分值 | 本项目抓手（已落地） |
|--------|------|----------------------|
| 功能完整性 | 30 | 上传解析、六维评分、诊断建议、岗位库匹配依据、优化稿 DOCX、报告、批量、模拟面试、教师一键成课 |
| 解析准确性 | 30 | 规则分块 + OCR；**分栏报告**：链路成功率 / 文本可读率 / 裁决后板块 F1 |
| 评价科学性 | 30 | 规则+语义融合（附录）、低信噪比扣分、证据置信度、可信度告警/封顶、技能图谱 |
| 技术创新性 | 10 | 实时 SSE 落库、版本 Diff、岗位适配依据、结构化提示词+护栏、标注裁决治理过程 |

### 1.3 相对「初步方案」时的短板：已补齐情况

| 原短板 | 现状 |
|--------|------|
| 匹配偏字面 | 已融合 jieba 同义 + 可选 SBERT；探索集 Fused−Rule 约 +0.24（**主答辩不作泛化结论**） |
| 交付停在建议列表 | 已出完整优化稿 DOCX + Diff；不足处【待补充】，不编造 |
| 缺可量化创新 | 平台验收（成功率/可读/护栏）+ 合成 F1 + **真实脱敏裁决后 F1≈0.98** |
| 体验缺少「智能体感」 | 上传实时解析流（SSE）+ 版本时光机 + 可信度分层 UI |
| 教师端缺班级抓手 | 一键成课（聚合短板，不落简历正文） |

### 1.4 简析智评三擎架构（包装主叙事）

> 简析智评采用「**语义理解、证据护航、生成交付**」三擎协同架构，形成从简历解析、岗位匹配、风险校验到优化交付的完整服务链路。

| 现有能力 | 包装名称 | 职责 |
|----------|----------|------|
| 双塔 SBERT（本地） | **语义理解引擎** | 理解简历与岗位语义关系，完成匹配排序 |
| 规则 / 分词基线（本地算法） | **证据护航引擎** | 学历硬约束、关键词核验、风险拦截、结果解释 |
| DeepSeek 等（可选云端） | **生成交付引擎** | 优化稿、建议、报告、模拟面试；无 Key 本地回退 |

```text
语义理解引擎：判断「简历和岗位是否匹配」
        ↓
证据护航引擎：判断「结论有没有依据、是否触发硬约束」
        ↓
生成交付引擎：转化为优化稿、报告和训练建议
```

**DeepSeek 只是生成交付引擎的可选云端实现，对外不叫「DeepSeek 引擎」。**

### 1.5 实际工程链路（与代码一致）

```text
上传（stream:true）
  → 创建 processing 记录
  → SSE /analysis-live（真实 pipeline 事件）+ 后台兜底
  → 解析 / OCR / 分块 / 结构化抽取
  → 证据护航：六维规则评分 + 低信噪比 + 硬约束 / 可信度分层
  → 语义理解：岗位匹配排序；岗位库 Top5 + 命中/缺失
  → 生成交付：技能图谱 + 优化稿 / Diff / 报告（可选云端润色，失败回退）
  → 落库 success
```

原则（已验证）：

- 无 API Key 可完整演示（证据护航 + 可选本地语义理解；生成交付走模板回退）  
- 本地演示无需 Redis（`USE_CELERY=false`）  
- 云端大模型不挡主链路  
- 优化稿不编造经历；不足处【待补充】  
- **成功率 ≠ 可读率 ≠ 板块 / 打分准确率**

## 二、对标结论（答辩用，保持简短）

多数竞品「全靠 LLM」或「纯向量」。本项目差异化已做成：

> **简析智评三擎：语义理解 + 证据护航 + 生成交付**，服务高校学生/教师就业数据治理闭环与优化稿交付

开源/论文/专利链接仍见文末附录；**不把运维向 Agent 安全门控专利当作本赛题主叙事**。  
**不把 61 条弱标注上的 SBERT Spearman 写进主 PPT。**  
**对外不称「DeepSeek 引擎」。**

## 五、接下来的打算（仅演示与材料）

> **功能与指标已冻结。** 以下不再扩需求；只允许修演示 P0 Bug。

### 5.1 UI

**不大改整体视觉。** 只保证演示关键页不懵：解析流、分层可信度、Diff、岗位依据显眼。

### 5.2 明确不做

| 不做 | 原因 |
|------|------|
| 再调 α / 扩 100+ 匹配集刷 Spearman | 同源探索，易被追问翻车 |
| Cross-Encoder、整站重设计 | 投入大、非主分 |
| 把 OCR 可读率说成解析准确率 | 口径违规 |
| 未授权真实简历进 git / 训练 | 合规风险 |
| 运维 Agent 安全专利当主卖点 | 与赛题主叙事不符 |

### 5.3 材料与答辩（仅剩）

1. 把 [`答辩材料速查.md`](答辩材料速查.md) **三层指标表**贴进 PPT（勿贴 SBERT 主结论）  
2. 录一条 2～3 分钟无配音演示备用  
3. 准备追问：幻觉怎么防、无 Key 怎么跑、成功率为何 ≠ 准确率、F1 口径是什么、为何不做微调验收  

### 5.4 节奏（冻结后）

| 焦点 | 动作 |
|------|------|
| 立即 | 2 分钟路径手测：上传→流→分层可信→Diff→岗位依据→下载 |
| PPT | 对齐收口页与速查；技术说明不改数字口径 |
| 彩排 | 只修卡点；非必要不改代码 |

## 六、风险与边界（仍有效）

1. 不用未授权真实学生简历明文训练或入库。  
2. 优化稿 / 建议不编造经历。  
3. 解析流事件必须来自真实中间结果。  
4. 教师端只推聚合短板，不广播简历正文。  
5. 运维安全类专利先申请、后公开，不进本赛题主卖点。  
6. Windows 本机 torch 若被智能应用控制拦截，见专用说明文档。  
7. **指标分栏**：L1 成功率、L2 可读率、L3 裁决后板块 F1；禁止混说。  
8. **61 条弱标注 SBERT / 融合分仅附录**，禁止写成平台泛化准确率。

## 七、结论

**深度优化与证据链收口均已完成。**
